# app/

## Purpose

Root directory of Next.js 15 App Router. Contains the entry point layout, global styles, error boundaries, route groups, and API routes for the ZERO-ONE study platform frontend.

## Key Files

| File | Description |
|------|-------------|
| `layout.tsx` | Root layout: HTML structure, Pretendard font loading, metadata, base body classes (`min-h-screen w-screen`) |
| `global.css` | **36KB theme file** — Tailwind CSS 4 `@theme inline` token definitions. Source of all design tokens (`--color-*`, `--spacing-*`, `--radius-*`, `--shadow-*`, `--font-*`). Base Tailwind scale classes (`p-4`, `rounded-lg`, `shadow-md`) are **PROHIBITED** — use only project custom tokens. |
| `global-error.tsx` | Root error boundary (`'use client'`). Catches errors outside route groups. Auto-reports to Sentry via `Sentry.captureException()`. Shows digest ID in dev mode for debugging. |
| `not-found.tsx` | Root 404 page (fallback when no route group's `not-found.tsx` catches). Shows image, heading, description, link to home. |
| `robots.ts` | SEO robots configuration (auto-generated by Next.js) |
| `sitemap.ts` | SEO sitemap configuration (auto-generated by Next.js) |

## Subdirectories

| Directory | Purpose |
|-----------|---------|
| `(admin)/` | Protected admin pages (`/admin/*`). Requires `ROLE_ADMIN` JWT claim. Has own `layout.tsx`, `error.tsx`, `not-found.tsx`. Contains admin-specific features. |
| `(landing)/` | Public landing page at `/`. No auth required. Has own `layout.tsx`, `error.tsx`, `not-found.tsx`. |
| `(service)/` | Authenticated service pages. Requires valid JWT in auth cookie. Includes: home, my-page, my-study, premium-study, group-study, mentoring, community, payment, insights, inquiry. Has own `layout.tsx`, `error.tsx`, `not-found.tsx`. Largest route group. |
| `api/` | Next.js API routes (server-only). Contains: auth refresh, email endpoints, Sentry proxy, custom server endpoints. |

## For AI Agents

### Working In This Directory

**Critical styling rules:**
- **Never use Tailwind base classes**: `p-4`, `rounded-lg`, `shadow-md`, `text-sm`, `gap-4`, etc. are prohibited.
- **Always use project custom tokens** from `global.css`: `p-200`, `rounded-150`, `shadow-2`, `font-designer-24b`, `text-text-default`, `gap-150`, etc.
- **No arbitrary values**: `p-[4px]`, `w-[320px]`, `top-20` are forbidden. Use only defined tokens.
- **Responsive breakpoints**: Use `md:`, `lg:`, `xl:` prefixes with custom tokens, not hardcoded pixel values.

**When modifying root files:**
1. `layout.tsx` — only for global metadata, font, or provider changes. Do not modify body styles.
2. `global.css` — theme token source. Modifications trigger styling changes across entire app.
3. `global-error.tsx` — root error boundary. Must preserve Sentry integration and error digest display.
4. `not-found.tsx` — 404 fallback. Ensure consistent branding with landing/service 404 pages.

**Route group structure:**
- Each route group `(admin)/`, `(landing)/`, `(service)/` has:
  - `layout.tsx` — group-specific layout (providers, headers, sidebars)
  - `error.tsx` — route segment error boundary (gated `process.env.NODE_ENV === 'development'` for tech details)
  - `not-found.tsx` — 404 page (group-specific styling)
  - `page.tsx` files — actual page components

**Authentication flow:**
- Middleware validates `accessToken` cookie before route group entry.
- Admin routes additionally check `ROLE_ADMIN` JWT claim.
- Failed auth redirects to `/` (landing page).
- Token refresh is automatic via axios interceptor (`AUTH001` → `/api/v1/auth/access-token/refresh`).

### Common Patterns

**Error boundaries:**
```typescript
// route group's error.tsx (e.g., (service)/error.tsx)
'use client';
import { analyzeError } from '@/utils/error-handler';

export default function Error({ error, reset }: { error: Error; reset: () => void }) {
  const errorInfo = analyzeError(error);
  
  return (
    <div>
      {process.env.NODE_ENV === 'development' && (
        <pre>{errorInfo.technicalMessage}</pre>
      )}
      <p>{errorInfo.userMessage}</p>
      <button onClick={reset}>Retry</button>
    </div>
  );
}
```

### API Routes

Located in `api/`:
- `/api/auth/*` — token refresh, logout
- `/api/sentry/*` — Sentry proxy (for error reporting)
- `/api/email/*` — email sending
- Server-side data fetching endpoints (via `src/api/endpoints/*.server.ts`)

Use for:
- Server-only operations (secrets, database access)
- Redirects from middleware
- Proxying backend APIs with auth headers

### Error Handling Strategy

1. **Route segment errors** → caught by route group's `error.tsx`
2. **Hydration/provider errors** → caught by `global-error.tsx`
3. **404s** → handled by route group's `not-found.tsx` (fallback: root `not-found.tsx`)
4. **Client mutations** → handled by component-level `onError` or global `MutationCache.onError` in `query-client.ts`

### Sentry Integration

- `global-error.tsx` auto-reports to Sentry via `Sentry.captureException()`
- Configured in `sentry.client.config.ts`, `sentry.server.config.ts`, `sentry.edge.config.ts`
- Source maps auto-uploaded on build (via `SENTRY_AUTH_TOKEN` in CI)
- `AUTH001` (token expired) excluded from reporting (normal flow)
