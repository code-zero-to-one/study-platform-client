# 시각 검증 규칙 (8b단계 + 8c단계)

`dev-start` SKILL.md에서 참조합니다. 페이지 생성(8단계) 후 이 규칙을 따릅니다.

---

## 8b단계. Chrome ↔ Figma 반복 시각 검증

**모든 페이지에서 필수.** 장식 레이어, 간격, 타이포그래피, 레이아웃, 인터랙티브 상태 전체 대상. 이전 세션 플랜 실행 시에도 필수입니다.

### 준비

1. 크로스 세션 플랜 실행 또는 새 세션 시작 시: `mcp__claude_ai_Figma__get_screenshot` 재호출로 최신 참조 이미지 취득
2. `mcp__chrome-devtools__navigate_page` → 라우트 URL
3. hover/인터랙티브 상태 검증이 필요한 경우: 스크린샷 전 `mcp__chrome-devtools__hover` 또는 `mcp__chrome-devtools__click`으로 활성화

### 비교 체크리스트 (매 반복마다 실행)

| 검사 항목 | 통과 조건 | 측정 방법 |
|---------|---------|---------|
| 요소 간 간격 | Chrome 간격이 Figma 간격과 일치 — 정확한 토큰 값 사용 (예: `gap-250`이 아닌 `gap-300`) | 시각적으로 측정; 불일치는 보통 4–8px 차이 |
| 인터랙티브 항목 패딩 | Figma `p-[Xpx]`와 일치하는 정확한 패딩 영역 | 클릭/hover 영역이 텍스트 + 패딩 범위와 일치해야 함 |
| 타이포그래피 | 요소별 글자 크기, 굵기, 색상이 Figma와 일치 | 텍스트 노드 명시적 비교 |
| 레이어 타입별 도형 수 | Chrome 수 == Figma 수 | 링·카드·스파클 각각 별도 카운트 |
| 컨테이너 내 콘텐츠 채움 | Figma와 유사한 비율 | 콘텐츠 vs 컨테이너 시각적 측정 |
| 요소 오버플로 | 의도한 컨테이너 밖으로 넘지 않음 | 카드, 패널 확인 |
| 도형 겹침 | 절대 위치 도형이 의도치 않게 합산되지 않음 | 각 도형이 독립적으로 읽혀야 함 |
| 툴팁/오버레이 위치 | 툴팁이 올바른 위치에 표시되고, 부모 스태킹 컨텍스트에 잘리지 않음 | 툴팁이 페이지 콘텐츠 위에 보이는지 확인 |
| 에셋 무결성 | 모든 Figma `<img src={imgX}>`에 로컬 대응 파일 존재 — 인라인 SVG, 텍스트 문자, CSS로 대체되지 않음 | 코드 vs Figma `const imgX` 목록 감사 |
| 인터랙티브 상태 정확도 | hover/focus/active 상태가 Figma variant와 일치 | 각 상태 트리거 후 스크린샷 |

### 반복 루프 (필수)

```
루프:
  1. mcp__chrome-devtools__take_screenshot → Chrome 상태
  2. 위 체크리스트 전체 항목에 대해 Chrome과 Figma 비교
  3. 실패한 ❌ 항목 전체 나열
  4. ❌ 항목이 없으면 → 루프 종료 → 8c단계 진행
  5. 각 ❌ 항목에 대해:
       a. 아래 근본 원인 표에서 원인 파악
       b. 코드에 수정 적용
       c. mcp__chrome-devtools__navigate_page (리로드)
  6. 1번으로 이동
```

**종료 조건:** 체크리스트의 모든 항목이 동시에 통과.
**❌ 항목이 남은 상태로 8b단계 종료 금지.** 시각적 불일치를 사용자에게 넘기지 말 것.
**최대 5회 반복.** 5회 후에도 실패 시 → S7 차단으로 기록하고 중단.

### 근본 원인 참조 표

| 증상 | 근본 원인 | 수정 |
|------|---------|------|
| 요소 간 간격이 너무 넓거나 좁음 | 간격 토큰 불일치 (예: `gap-250` 대신 `gap-300` 사용) | Figma `gap-[Xpx]` 읽기 → 정확한 토큰으로 매핑 |
| 항목 히트 영역 또는 시각적 패딩 잘못됨 | 탭/항목 래퍼에 `p-[token]` 누락 | Figma에 맞는 패딩 토큰 추가 |
| 툴팁 또는 플로팅 요소가 페이지 콘텐츠 뒤로 잘림 | 부모 요소에 `mix-blend-multiply` / `filter` / `transform` → 스태킹 컨텍스트 생성; 형제 `<main>`이 위에 렌더링 | 부모 요소에 `relative z-{n}` 추가하여 스태킹 컨텍스트가 `<main>` 위에 오도록 함 |
| Figma보다 같은 형태 도형이 더 많이 표시됨 | 기존 요소와 동일한 시각 형태의 새 요소 추가 → 합산됨 | 중복 제거 또는 새 요소의 형태 변경 |
| 컨테이너 안 콘텐츠가 너무 작음 | 페이지 레벨 호출에서 크기 추정 (2e단계 미실행) | 컨테이너 노드 재드릴, 정확한 px 적용 |
| 콘텐츠가 컨테이너 밖으로 넘침 | `overflow-hidden` 없거나 치수가 컨테이너 초과 | `overflow-hidden` 추가 또는 치수 축소 |
| 아이콘/일러스트가 색상, 굵기, 형태에서 다름 | 다운로드한 Figma 에셋 대신 수제 SVG/텍스트/CSS로 대체 | `curl`로 실제 에셋 다운로드, 근사물을 `<img src="/public/...">` 로 교체 |
| 텍스트 내용 불일치 (오타, 대소문자) | Figma 텍스트 잘못 읽거나 다른 노드 variant 샘플링 | Figma 노드 텍스트 필드 정확히 재독 — 그대로 복사 |

## 8c단계. 문제 문서화

**8단계 또는 8b단계에서 수정이 적용된 경우 필수.**

각 문제 (시각적 불일치, 레이아웃 오류, 스태킹 컨텍스트 문제, 잘못된 토큰 등):

1. `docs/Figma/problems/{page-slug}-problems.md` 생성 또는 추가
2. 아래 템플릿으로 각 문제 기록:

```markdown
## 문제: {짧은 제목}

### 증상
{잘못된 시각적/기능적 동작}

### 근본 원인
{발생 이유 — 특정 CSS 속성, 잘못된 토큰, 누락된 규칙, 브라우저 동작, 아키텍처 제약}

### 적용된 수정
{정확한 코드 변경 — 파일 경로, 변경 전/후}

### 예방 방법
{이 문제를 더 일찍 발견할 수 있는 규칙 또는 검사}
```

**예시 — 스태킹 컨텍스트 툴팁 잘림:**

```markdown
## 문제: 툴팁이 배너 콘텐츠 뒤에 잘림

### 증상
"Coming Soon" 네비 툴팁이 화살표 끝만 보이고, 배지 본체가 페이지 배너 뒤에 숨겨짐.

### 근본 원인
`<header>`의 `mix-blend-multiply`가 CSS 스태킹 컨텍스트를 생성함.
명시적 z-index 없음 → DOM 순서가 페인트 순서 결정.
`<main>`이 DOM에서 `<header>` 뒤에 오므로 헤더의 전체 스태킹 컨텍스트 위에 페인트됨.
내부 자식의 `z-50`은 해당 스태킹 컨텍스트를 벗어날 수 없음.

### 적용된 수정
`home-header.tsx`의 `<header>`에 `relative z-10` 추가:
  변경 전: `<header className="bg-background-default py-125 mix-blend-multiply">`
  변경 후:  `<header className="relative z-10 bg-background-default py-125 mix-blend-multiply">`

### 예방 방법
부모 요소에 `mix-blend-multiply`, `filter`, `transform`, `opacity < 1`, `will-change`, `isolation: isolate`가 있으면
스태킹 컨텍스트를 생성한다고 가정하고, 자식이 DOM 형제 위에 오버레이해야 하는 경우
부모에 양수 `z-index`를 부여할 것.
```

8단계/8b단계에서 수정이 없었다면 이 단계 생략.
