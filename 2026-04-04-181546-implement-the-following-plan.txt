⏺ ★ Insight ─────────────────────────────────────
  이 패턴은 "blob URL → 매크로 placeholder" 변환의 핵심이다.
  에디터 내부에서는 이미지가 blob:http://... URL로 표시되지만,
  서버 제출 시 @@randomId.png@@ 형태로 교체돼야 실제 업로드가 가능하다.
  replaceFirstImageSource가 이 변환을 담당한다.
  ─────────────────────────────────────────────────

  replaceFirstImageSource는 폼 제출 직전,
  serializeGroupStudyDescriptionForRequest가 호출될 때 실행됩니다.

  실행 흐름

  사용자가 폼 제출 버튼 클릭
    └─ serializeGroupStudyDescriptionForRequest({ content, pendingImages })
         ├─ extractHtmlImageUrls(normalizedContent)
         │    → HTML 내 모든 img[src] URL 추출
         │
         └─ for each imageUrl:
              if (pendingImageMap.has(imageUrl))  ← blob: URL인 경우
                replaceFirstImageSource({
                  html: nextDescription,
                  currentSource: "blob:http://localhost/...",  // 에디터 표시용
                  nextSource:    "@@abc123.png@@",             // API 전송용
  매크로
                })

  구체적 트리거 조건

  - 콘텐츠에 pendingImages(사용자가 업로드한 파일들)가 1개 이상 존재할 때
  - extractHtmlImageUrls가 반환한 URL 중 pendingImageMap에 매칭되는 blob URL이
  있을 때

  즉 에디터에서 이미지를 첨부했을 때 폼 제출 시 한 번 실행되고, 텍스트만 입력한

  2. utils/markdown-content-images.ts

  이미지 URL 추출·검증 전용. 정규식 2개가 핵심.

  상수: 2개 정규식

  MARKDOWN_IMAGE_PATTERN = /!\[[^\]]*]\(([^)\s]+)(?:\s+"[^"]*")?\)/g
  마크다운 ![alt](url) 또는 ![alt](url "title") 형식. 캡처 그룹 1 = URL.

  /<img[^>]+src\s*=\s*(?:"([^"]+)"|'([^']+)'|([^\s>]+))/gi
  HTML <img src="..."> 형식. 3가지 quote 방식 대응: 큰따옴표(1), 작은따옴표(2),
  따옴표 없음(3).

  normalizeMarkdownImageUrl(url) — private

  URL 앞뒤 공백 제거 + <url> 형식의 꺽쇠 제거. (<url> 표기는 마크다운 spec 중
  하나)

  isRelativeImagesPath(url) — private

  /images/로 시작하는 경우 상대 경로로 판단.

  getUrlPathExtension(url) — private

  URL에서 파일 확장자 추출. URL 파싱 시도 후 실패하면 ?/# 제거 후 마지막 . 이후
  추출.
  - 조건: try { new URL(url).pathname } → URL 형식이면 pathname 추출, 아니면
  fallback.

  getFileExtension(fileName: string): string

  파일명에서 확장자 추출. split('.').pop() — 파일명이 image.tar.gz면 gz 반환.

  extractMarkdownImageUrls(markdown: string): string[]

  최적화 조건: !와 ][가 없으면 조기 반환 (정규식 실행 비용 절감).
  matchAll로 전체 매칭 후 각 캡처 그룹 1 URL을 normalizeMarkdownImageUrl로 정제.

  isHttpsImageUrl(url: string): boolean

  URL이 안전한 이미지 URL인지 확인.
  - /images/로 시작 → true (상대 경로 허용)
  - new URL(url).protocol로 파싱 → https: 또는 http: → true
  - 파싱 실패 → false

  hasAllowedImageExtension(url, allowedExtensions): 확장자 허용 여부

  getUrlPathExtension으로 URL에서 확장자 추출 후 allowedExtensions 배열에
  포함됐는지 확인.

  extractHtmlImageUrls(html: string): string[]

  최적화 조건: <img가 없으면 조기 반환.
  matchAll로 전체 매칭, 3개 캡처 그룹 중 첫 번째 non-null 값 사용.

  extractImageUrls(content: string): string[]

  통합 진입점. isHtmlContent 분기:
  - HTML → extractHtmlImageUrls
  - 마크다운 → extractMarkdownImageUrls

  handleImageFiles(editor, files) — useCallback

  다중 파일 처리. 가드 조건:
  - !resolvedImageConfig || files.length === 0 || isUploadingImages → return

  1. extractImageUrls(editor.getHTML()).length → 현재 이미지 수 확인
  2. remaining = Math.max(0, maxImageCount - existingCount) → 남은 슬롯
  3. remaining === 0 → 에러 메시지 설정 후 return
  4. 파일 순회:

  decodeHtmlEntities(value: string): string

  HTML 엔티티 문자열을 실제 문자로 변환한다.

  - &nbsp; → 공백
  - &amp; → &
  - &lt; → <
  - &gt; → >
  - &quot; → "
  - &#39; → '
  - &#(\d+); — 10진수 코드포인트 → String.fromCodePoint(parseInt(decimal, 10))
  - &#x([\da-f]+); — 16진수 코드포인트 → String.fromCodePoint(parseInt(hex, 16))

  각 교체는 replace를 체이닝한다. 마지막 두 개는 콜백 함수로 그룹 캡처값을
  변환한다.

  isHtmlContent(content: string): boolean

  세 패턴 중 하나라도 매치되면 HTML로 판단한다.

  HTML_OPEN_TAG_PATTERN.test(content)   // 여는 태그 있음?
  || HTML_CLOSE_TAG_PATTERN.test(content)  // 닫는 태그 있음?
  || HTML_SELF_CLOSING_TAG_PATTERN.test(content)  // 자기닫힘 태그?

  TipTap 에디터는 항상 HTML을 내보내므로, 이 함수가 "에디터 출력 vs 마크다운
  텍스트"를 구분하는 분기점이 된다.

  HTML_MEDIA_TAG_PATTERN으로 img, video, audio, iframe, embed 태그 존재 여부만

  4. utils/markdown-content-normalize.ts

  역할: 에디터 출력값을 "의미 있는 콘텐츠인가"로 정규화한다.
        빈 HTML(<p><br></p>)을 빈 string으로 만들어 form validation과 연결한다.

  normalizeMarkdownContent(content: unknown): string

  1. toNonEmptyTrimmedString(content)  // string 아니면 '', 공백만이면 ''
  2. if (!isHtmlContent(trimmed)) return trimmed  // 마크다운은 그대로
  3. if (hasHtmlMediaTag(trimmed)) return trimmed  // 이미지/영상 포함이면 보존
  4. return getRichContentVisibleText(trimmed).length > 0 ? trimmed : ''
     // 가시 텍스트가 없으면 '' → <p><br></p> 같은 빈 HTML 처리

  핵심 케이스: TipTap에서 내용을 모두 지우면 <p><br></p> HTML이 나온다. 이걸
  그냥 두면 description 필드가 비어 있지 않아 validation을 통과한다. 이 함수가
  그 경우를 ''으로 변환해 min(1) Zod 검증이 작동하게 한다.

  ---
  uploadAndInsertFile(editor, file) — useCallback

  파일 1개를 업로드하고 에디터에 삽입한다.

  if (!resolvedImageConfig) return  // config 없으면 무시
  publicUrl = await resolvedImageConfig.uploadImageFile(file)
  editor.chain().focus().setImage({ src: publicUrl, width: 200 }).run()

  ---
  handleImageFiles(editor, files) — useCallback

  여러 파일을 받아 개수 제한, 검증, 업로드를 순차 처리한다.

  if (!resolvedImageConfig || files.length === 0 || isUploadingImages) return

  existingCount = extractImageUrls(editor.getHTML()).length
  remaining = max(0, maxImageCount - existingCount)
  if (remaining === 0) → setImageInsertError("최대 N개") return

  for file of files:
    if (validFiles.length >= remaining) → hitLimit = true; break
    error = validateImageFileForUpload(file, config)
    error ? errors.push(error) : validFiles.push(file)

  if (validFiles.length === 0) → setImageInsertError(errors.join(' ')); return

  setIsUploadingImages(true)
  try:
    for file of validFiles:
      try: await uploadAndInsertFile(editor, file)
      catch: errors.push("파일명: 업로드 실패")

    if (hitLimit) errors.push("최대 N개...")
    if (errors.length > 0) setImageInsertError(errors.join(' '))
  finally:
    setIsUploadingImages(false)

  hitLimit 플래그: 파일이 제한 초과해도 가능한 만큼은 업로드하고, 마지막에 경고
  메시지를 추가한다.

  handlePasteImageSource(editor, source) — useCallback

  validateImageFileForUpload → 실패 시 에러
  uploadAndInsertFile(editor, file)

  catch: setImageInsertError("URL을 가져올 수 없습니다. 이미지를 직접 복사...")

  안내한다.

  ---
  readClipboardImageFiles() — useCallback

  Clipboard API(navigator.clipboard.read())로 클립보드에서 직접 이미지를 읽는다.

  escapeAtSymbols(html: string) (내부)

  @를 \@로 이스케이프하되 @@macro@@ 패턴은 보호한다.

  1. @@...@@ 패턴을 \uFFF0MACROi\uFFF0 임시 플레이스홀더로 치환
  2. 나머지 @ → \@
  3. 임시 플레이스홀더 → 원래 @@...@@ 복원

  이스케이프 이유: 서버 측에서 @ 기호를 특수 문자로 처리할 수 있기 때문.

  ---
  replaceFirstImageSource({ html, currentSource, nextSource }) (내부)

  HTML 문자열에서 특정 src를 가진 첫 번째 <img>를 찾아 src를 교체한다.

  currentSource를 정규식 특수문자 이스케이프 후:

  1. 쌍/홑따옴표 패턴 먼저 시도 → 매치 시 교체
  2. 인용부호 없는 패턴 fallback

  nextSource.replace(/\$/g, '$$$$') — $1 같은 캡처그룹 참조가 교체 문자열로
  오해되지 않도록 이스케이프.
